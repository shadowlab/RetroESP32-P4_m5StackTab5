# RetroPad board firmware

Firmware for the [console boards](../boards/README.md), which are all built on a **Microchip
AVR32DD28** (SOIC-28). One image serves every board. It speaks the RetroPad I2C protocol:
client address 0x6D, M5Stack's keyboard registers plus the RetroPad block 0x70–0x87, see
[`retropad_proto.h`](../../../components/tab5_ctrl/include/retropad_proto.h).

| File | What it is |
|---|---|
| `main.c` | The firmware (about 2.1 KB of the 32 KB flash) |
| `pinmap.h` | Generated by `boards/kicad_gen/gen_avrdd_pinmap.py` from `boards/layout.py`: for each console ID, which RetroPad bit each of the 13 button pins carries, plus the console-select list and LED colours |
| `test/` | Host test: builds `main.c` against fake registers and replays the Tab5 driver's I2C traffic |

## What it does

* **Clock:** 24 MHz internal oscillator; buttons are scanned every 1 ms (TCB0).
* **Buttons:** PD1–PD7, PC0–PC3 and PF0–PF1 are inputs with internal pull-ups, and a pressed
  button reads low. A change counts once it has been stable for 5 ms.
* **Console ID:** read from 0 Ω straps on PA0, PA1, PA6 and PA7 (pulled to GND = bit set) at
  boot and again every 100 ms. A new ID takes effect after two equal readings in a row. The ID
  selects the pin map row.
  * Every console ID has a row.
  * IDs with no board layout yet use a generic order, so a slot can never default to UP.
* **Console select** (straps read `SELECT_STRAP_ID` = 14, the NES / Game Boy / Master System
  board): the straps are not re-read. The console comes from EEPROM byte 0 (blank or out of
  range = the first entry, NES), and each press of the button on PC3 (debounced 20 ms) steps
  to the next entry of `select_console[]` and saves it. The SK6812 LED on PC2 shows it in that
  console's colour (`select_grb[]`): sent at boot, on each press and every second. The LED
  driver is a cycle-counted assembly loop (30 cycles = 1.25 µs per bit at 24 MHz) run with
  interrupts off for about 35 µs; the I2C client stretches the clock meanwhile.
* **Analog:** PA4/PA5 (AIN24/AIN25) are read as 8-bit values, but only for the Atari 2600 and
  5200 IDs.
* **Unused pins don't float:** PA4/PA5 have their digital input buffers off on every board, and
  an unfitted console-ID strap keeps its pull-up. A fitted strap (tied to GND) has its pull-up
  and input buffer turned off after the ID is read, so it draws no current.
* **I2C client** (TWI0 on PA2 SDA, PA3 SCL; interrupt driven):
  * Implements what the host driver uses: the 0x70–0x87 block, FW_VERSION (0xFE = 0x22), and
    INT_CFG / EVENT_NUM / KB_MODE writes.
  * A read takes a snapshot first, so the 4-byte button mask is always coherent.
  * The stock keyboard's event, HID and character modes are not implemented. The key-event
    register always reports an empty queue.

## Build and flash

The AVR DD needs avr-gcc 13 or newer with avr-libc 2.2 or newer. Ubuntu's `gcc-avr` is too
old. Zak Kemble's prebuilt
[avr-gcc 14.1](https://github.com/ZakKemble/avr-gcc-build/releases) works:

```
make AVR_GCC_DIR=/path/to/avr-gcc-14.1.0-x64-linux
make flash PORT=/dev/ttyUSB0          # SerialUPDI: USB-serial adapter + resistor
```

The board's J2 is the UPDI header: 1 = 3V3, 2 = UPDI, 3 = GND. MPLAB Snap / PICkit 4 work
too (`avrdude -c snap_updi` / `pickit4_updi`).

## Testing

```
test/run_host_test.sh
```

This builds the real `main.c` on the host and replays what `components/tab5_ctrl` does:
* probes FW_VERSION and the RPAD info block (signature, protocol, console ID 3, no analog);
* writes INT_CFG / EVENT_NUM;
* polls the 8-byte button/analog block before and after the debounce, with UP + A + R held,
  then with UP released;
* checks that the client completes a read when the host NACKs.

It also runs a console-select board: straps reading 14, a blank EEPROM starting on NES, the
select button's debounce (a short bounce is ignored, a held press steps once), NES → Game Boy →
Master System → NES with the choice reported over I2C, saved to EEPROM once per press and shown
on the LED, and the saved or an out-of-range EEPROM value at boot. It checks the strap re-read
(only a second equal reading takes effect, and a single glitch doesn't), then switches the ID straps to NES, Game Boy,
Master System and Genesis and checks that
each board's pins map to the right bits, and checks the generic fallback for an ID without a
layout. All pass.

The firmware has not run on real hardware yet, and no AVR DD simulator was available.
